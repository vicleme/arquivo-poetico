# Export for AI: Nested vs. Flat

The app offers two export formats designed for use with AIs (ChatGPT, Claude, Gemini, etc.). Choosing the right format makes a difference in the result.

---

## Nested Format

Generated by the **"Exportar Aninhado"** ("Export nested") button in the page header, next to "Download JSON". It has no filter: it always takes the whole collection.

The file structure mirrors the actual hierarchy of the collection: each Book contains its Parts, each Part contains its Sections, each Section contains its Poems and Prose — nested inside one another. Collections come fully resolved (with each item's actual content inline, not just ID references).

A Poem or Prose that appears in more than one book (or in more than one place) comes out once in each place, with the position it has there. Because the tree already says where each copy sits, these copies carry no `aparece_em` list. A text that only "consta" in a book (it is linked to the book, with no Part, Section or position) is not in the tree: it comes apart, in the book's `conteudo_poemas_vinculados` and `conteudo_prosas_vinculadas` keys. So when counting texts from this file, count by `id`, not by how many times a title shows up.

**Use when the task involves the collection as a whole or the relationships between parts:**

- Analyzing the thematic arc of a book
- Identifying patterns across sections or across books
- Generating an annotated index or a structured synopsis
- Asking the AI to understand a work's internal progression
- Comparing one book's phase with another's

The advantage here is that the hierarchy is explicit in the shape of the data — the AI doesn't need to infer that a given poem belongs to a given section; that's already visible in the JSON structure. Less inference means less chance of error and fewer tokens spent on deductions the file could have done on its own.

**Limitation:** a file with the entire collection can be large. Check that it fits within the context limit of the model you're using before sending it.

---

## Flat Format (filtered)

Generated by the **"Baixar JSON seletivo"** ("Download selective JSON") button on the Export tab, by selection from the Poems/Prose listing ("⬇ JSON" in the bulk actions bar), or by the **"Export selected"** button on the Structure tab (the latter uses its own structure, with no resolved context — see the dedicated section below).

The structure is a flat list of items. Each record is self-contained: it carries the text, context already resolved into readable text (Book, Part, and Section names), tags, people, dates. There's no nesting — it's an array of independent objects.

The `contexto` of each record has `livro`, `parte` and `secao` for the text's Destination only (its first appearance that has a place). When the text appears in more than one place, `contexto.aparece_em` lists all of them, each as `{ livro, parte, secao, posicao, coletanea, principal }`: `posicao` is empty when the text only "consta" in the book, `coletanea` is true when the place is an Anthology, and `principal` marks the main appearance (the one in the book published earliest), which is not always the Destination. In `.csv` this is the `aparece_em` column, with the places separated by `" | "` (empty when there is only one place). In `.md`, `.pdf` and `.docx` the "Aparece em" line only shows up when the text has two or more appearances in regular books.

**Use when the task is to process items individually:**

- Writing a critical comment on each poem
- Suggesting or correcting tags for each text
- Translating or adapting poem by poem
- Classifying texts by theme, tone, or period
- Feeding an external pipeline that expects tabular records

In this case, nesting would be counterproductive: to reach a specific poem the AI would need to "descend" several levels of the tree, consuming context without adding anything. The flat format delivers each item already self-explanatory.

**Whole collection, flat:** the same tab also has the buttons **"Baixar tudo - JSON flat"**, **"Baixar tudo - .md"**, **"Baixar tudo - .pdf"** and **"Baixar tudo - .docx"**, which take the entire collection in this flat model with no filter to set.

**Extra advantage:** the filters on the Export tab (by person, theme, year, status, book) let you send just the relevant subset — especially useful when the whole collection doesn't fit the model's context.

## One-off export via the tree

On the **Structure** tab, you can mark individual items directly in the book's tree (checkboxes on each row) and export just those via **"Export selected"**. The result is a structural JSON (books/parts/sections/poems/prose/elements as separate collections) with exactly the marked items — with no resolved context and no Markdown option.

Use this when you want to pick specific poems or sections without needing to describe an attribute-based filter — for example, "I want these three poems and that whole section, but not the rest of the book."

---

## One-off export via the Poems/Prose listing

On the **Poems** and **Prose** tabs, checking items via the table's selection boxes and using **"⬇ JSON"** or **"⬇ MD"** in the bulk actions bar exports only the marked items — in the same flat structure as Selective export (`{ export_format: 'selection', items: [...] }`), with context (Book/Part/Section) already resolved, and also available in Markdown. Unlike the one-off export via the tree (which only produces structural JSON with no resolved context): here each item already comes self-explanatory, the same way as in Selective export.

Use this when the items you want don't form an easy filter to describe (e.g., "these 4 specific poems, written in different years, with no shared theme") and you're already browsing the listing anyway — or when you want the result in Markdown, which the tree export doesn't offer.

## Shared lines at the top of multi-text exports

In `.md`, `.pdf` and `.docx` downloads with more than one text, a metadata line (`- **Label:** value`) that every text has with exactly the same value is written once, under **"Comum a todos os textos"** ("Common to all texts") near the top, and is left out of each text. The labels considered are Autoria, Fonte, Edição, Link da fonte, Grafia, Texto conferido, Domínio público, Corrente literária and Idioma. The rule is strict, per label: a text missing the line, or with another value, keeps that line in every text. So when you read a text below, any of those lines that is not there is either in the shared block or was empty.

The **"Agrupar no topo"** box (under "Opções de download") (on by default, remembered in the browser) turns this off. `.json` and `.csv` never change, and a single-text download always has every line.

---

## Person role legend

The selection, selective export, flat all and template `.json` files, and the multi-text `.md`, carry a legend of the Person roles used by the exported texts (`legenda_papeis_pessoa` key in `.json`, "Legenda dos papéis de Pessoa" section in `.md`). Details in `pessoas-papeis-for-ai.md`. The `.csv` has no legend. The **"Infos de papel"** box chooses whether the file comes with or without it. There are two independent choices, both on by default and saved in the browser: one for downloading several texts ("Download options" of the selection bar and the Export tab) and one for downloading a single text (the column's Actions panel and the View modal).

---

## Quick summary

| Situation                                                                              | Recommended format               |
| -------------------------------------------------------------------------------------- | -------------------------------- |
| Analyzing structure, arc, progression of a book                                        | Nested (all)                     |
| Processing texts one by one (commenting, translating, classifying)                     | Filtered flat                    |
| Picking one-off items by browsing the tree                                             | Flat via Structure tab           |
| Picking one-off items in the Poems/Prose listing, with resolved context or in Markdown | Flat via listing (JSON or MD)    |
| Large collection that doesn't fit the model's context                                  | Flat filtered by book/theme/year |
